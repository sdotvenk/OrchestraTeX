Score

Design C treats OrchestraTeX as an Overleaf-grade LaTeX IDE where agents behave like co-authors: they show up in the file tree, the source, the PDF and a shared timeline, each in its own ink. Chat is a flowing transcript; only decisions get a raised surface.

01

Colour means who

Every harness gets one ink and a soft tint. That ink marks its thread, its live cursor, its gutter edits, its PDF changes and its lane in the Score. State never borrows a voice colour: waiting is amber with a lock glyph, errors red with a label.

02

Work happens in the document

Agents edit with a named cursor and a tinted range, like a collaborator in Overleaf. Keep or undo sits next to the lines. The preview says how many edits it is behind; ⌘↵ rebuilds it.

03

The Score shows the ensemble

The bottom drawer has lanes for every active thread and for you: reads, edits, compiles and waits plotted over time. Click a mark to open the file or diff. Problems, the build log and the terminal share the drawer.

04

Chat flows, decisions stand

The transcript is one reading column with a thin voice line. Tool activity hangs off that line as small marks and folds to a summary. Permission requests are the only raised cards, compact and amber, with exact command and cwd.

05

Overleaf where it already works

File tree with create, upload and rename beside it. Code and Visual modes. Recompile on the preview. SyncTeX jumps both ways. History of labelled versions. T3 adds threads, approvals, queues and the project inspector.

06

Depth from print

Warm frame, inset sheets with hairlines and a 1 px lift. Floating items cast a soft shadow. The one primary action per view is solid ink with an offset tangerine shadow, like a misregistered press print.
